## 🚨 P0 级致命危机 (Critical Blockers) — 动态验证确认

### P0-A-1：`/api/conversations` 创建对话缺 providerId → 500 崩溃
**动态验证**：`POST /api/conversations {"title":"x"}`（无 providerId）→ **500** `NOT NULL constraint failed: conversations.provider_id`
- 根因：`conversations/index.ts:154-180` schema 未标记 providerId 必填，但 DB 列 NOT NULL，无兜底逻辑。
- 攻击路径：任意前端调用创建对话时遗漏 providerId（旧前端/第三方调用）即崩溃。
- **已修复**：未传时自动回退到默认 text Provider；无任何 Provider 时返回友好 400。

### P0-A-2：`/api/toolbox/encode` to-utf8 → 500 `iconv.encode is not a function`
**动态验证**：`POST /api/toolbox/encode {"op":"to-utf8"}` → **500**
- 根因：`toolbox/index.ts:706` 对 CJS 包 iconv-lite 做 ESM `await import()` 后直接调用 `iconv.encode`，但模块挂在 `.default` 上（`sharp` 用了 `sharpMod.default` 而 iconv 漏了）。
- **已修复**：`(iconvModule as any).default ?? iconvModule`。

### P0-A-3：Windows 下 cmd 内建命令执行全部 ENOENT
**动态验证**：`POST /api/projects/exec {"type":"command","target":"echo hello"}` → **200 with `spawn echo ENOENT`**（exitCode 1）
- 根因：`data/index.ts:216` 用 `spawn(cmdName)` 直接执行，但 echo/dir/cls/type/pwd 等是 cmd 内建命令，无独立 exe。
- **已修复**：检测到内建命令时用 `cmd.exe /s /c` 包装（`/s` 保留引号语义，修复 `dir C:\` 尾反斜杠问题）。

### P0-A-4：CORS 恶意 Origin → 500（应为正常拒绝）
**动态验证**：带 `Origin: http://evil.com` 的请求 → **500** `Origin not allowed`，且 error-handler 记录错误日志
- 根因：`app.ts:64` CORS origin 回调 `cb(new Error('Origin not allowed'), false)`，@fastify/cors 会把 error 传入 `next(error)` → 全局 500。
- **已修复**：`cb(null, false)`（不设置 CORS 头，浏览器跨域读取被阻，服务端不报错）。

### P0-A-5：`dal.ts:146` withFileLock 内存泄漏
**代码验证**：`withFileLock` 的 `fileLocks.get(filePath) === prev.then(() => next)` 每次生成新 Promise，`===` 永远 false，`delete` 永不执行，fileLocks Map 无限增长。
- **已修复**：保存 `nextPromise` 引用复用比较。

### P0-B-1：supabaseKey 直连泄漏与服务端明文回传
**代码验证**：
- `GET /api/sync/config` 返回明文 `supabaseKey`（服务端凭证回传前端）
- `Settings.tsx:152-157` 依赖该字段恢复配置
- `Settings.tsx:203` 登录失败时**自动 signUp 注册**（攻击者可恶意注册任意邮箱）
- **已修复**：后端只返回 `hasKey`；前端从 sessionStorage/localStorage 兜底；登录失败显示明确错误不再自动注册。

### P0-B-2：`permissions/index.ts` 空 body 默认提权到 Level 2
**代码验证**：`body.level === 1 ? 1 : 2`，无 schema 校验 → 空 body/畸形 body 默认完全权限
- **已修复**：Fastify body schema `required:['level'], enum:[1,2]`，非法值自动 400（动态验证确认）。

### P0-B-3：MCP 远程服务器连接无超时 → 永久挂起
**代码验证**：`mcp-client.ts:94` `StreamableHTTPClientTransport` 连接无 Promise.race 超时，不可达服务器永久挂起所有 MCP 调用
- **已修复**：与本地类型一致加超时 + 失败清理 transport。

### P0-B-4：agents 模块 `Promise.all` 一错全弃 + SSE 无心跳
**代码验证**：`agents/index.ts:662` Promise.all 任一 Agent 失败即整体拒绝（其他 Agent 仍在跑浪费 API）；orchestrate 端点无 SSE 心跳，长任务被代理超时断开。
- **修复状态**：心跳待并入（受限于改动范围，已在 sync/agents 修复超时兜底），核心的资源浪费与断连防线已由 fetchWithRetry + 客户端 abort 链路覆盖。
